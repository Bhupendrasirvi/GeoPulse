1. Introduction

During disasters like flash floods, structural fires, or building collapses, getting help quickly is critical. Traditional emergency helplines often waste precious minutes because operators have to manually write down addresses and figure out who is nearby.

GeoPulse is a fast, web-based emergency dispatch platform. It allows citizens in danger to broadcast their GPS coordinates and emergency type directly to a central command map, where the system automatically finds and assigns the closest available rescue squad in seconds using MongoDB's built-in location search.

2. Project Objectives

  • Sub-20ms Location Matching: Use MongoDB's 2dsphere index to find the nearest rescue team within 15 km in less than 20 milliseconds.
  • Simple Citizen SOS Portal: Give citizens a one-tap web form to drop their pin, pick their emergency category, and request help.
  • Autonomous 48-Hour Cleanup: Use MongoDB's Time-To-Live (TTL) feature to auto-delete resolved alerts after 48 hours without needing manual cleanup scripts.
  • Smart Report Stacking: Group duplicate calls from the same location into a single card with a counter (e.g. x3 reports) to prevent screen clutter.
  • Local Backup Team Creation: Automatically register a local community squad if no team exists within 15 km so no victim goes unattended.
  • No Complex External Brokers: Keep the system simple with Node.js and MongoDB without needing Redis or Kafka.

4. How the System Works

A. For Citizens in Need:

  1. Open the portal and click "Use My GPS" or click on the map.
  2. Select the emergency category (Medical, Flood, Fire, Food).
  3. Enter contact details, number of people trapped, and a short note.
  4. Click "Transmit Emergency SOS Beacon". The alert is saved immediately into MongoDB.

B. For Dispatchers & Coordinators:

  1. The dispatcher sees a clean, color-coded feed of open emergencies (Red = Action Needed, Blue = En Route, Green = Resolved).
  2. Click "Match Unit" (or press M). The system queries MongoDB and draws a blue route line to the nearest squad.
  3. When rescue is complete, click "Resolve" (or press R). This activates the 48-hour auto-delete timer.

6. Key Features & Implementation

Feature 1: Finding Nearest Team using `$geoNear`

Instead of calculating distances manually in JavaScript, MongoDB computes spherical distance directly: 

// MongoDB query in server.js
const pipeline = [
  {
    $geoNear: {
      near: { type: "Point", coordinates: [lng, lat] },
      distanceField: "distanceMeters",
      spherical: true,
      maxDistance: 15000 // 15 km search radius
    }
  },
  { $limit: 1 }
];
const nearestTeam = await db.collection('responders').aggregate(pipeline).toArray();

Feature 2: 48-Hour Self-Cleaning (TTL Index)

// MongoDB TTL Index setup
db.incidents.createIndex(
  { resolvedAt: 1 }, 
  { expireAfterSeconds: 172800 } // 48 Hours = 172,800 Seconds
);

Once marked resolved, MongoDB automatically removes the record after 48 hours without requiring background cron scripts.

Feature 3: Keyboard Accelerators for Dispatchers

  • / — Jump to search bar
  • J / K — Move up/down through incident list
  • M — Match and dispatch nearest squad
  • R — Mark incident as resolved
  • N — Simulate incoming emergency call

7. How to Run the Project

  1. Start MongoDB: Make sure MongoDB is running on your machine (net start MongoDB).
  2. Start Backend: Open terminal in geopulse-backend and run node server.js.
  3. Open Frontend: Open geopulse-frontend/index.html in any web browser, or double click start.bat.

8. Conclusion

GeoPulse proves that an effective, mission-critical emergency response system does not require over-complicated cloud architectures. By taking full advantage of MongoDB's built-in geospatial queries and TTL indexes alongside a clean, responsive Leaflet map, GeoPulse delivers reliable, sub-second dispatch coordination to help save lives during disasters.
