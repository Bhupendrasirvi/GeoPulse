Abstract

During emergencies such as road accidents, building fires, and severe weather floods, fast communication and prompt rescue team dispatch are critical to saving lives. In standard systems, emergency calls are often handled manually over the phone, where callers struggle to describe exact locations, leading to dispatch delays and wasted travel time.

GeoPulse is a real-time web-based emergency incident and dispatch coordination system designed to solve this problem. The application allows citizens in distress to submit emergency alerts along with their exact GPS coordinates, type of emergency, and number of people requiring assistance. On the coordinator side, an interactive live map displays all reported incidents and active rescue units in real time.

Key Features of the Project

  • Real-Time Proximity Matching: Uses MongoDB's 2dsphere index and $geoNear aggregation pipeline to quickly find the nearest available rescue squads to an incident.
  • Citizen SOS Submission: An easy-to-use reporting form that captures GPS location with one click, emergency category, and severity.
  • Interactive Map Dashboard: Built using Leaflet.js to visualize incidents (red markers), rescue teams (blue markers), and relief shelters (green markers).
  • Dynamic Route Line & ETA: Displays a visual route line connecting the assigned rescue team directly to the incident pin, along with calculated distance and ETA.
  • Automatic Data Purge (TTL): Implements MongoDB TTL indexing on resolved incidents so old records are cleaned up after 48 hours.
  • Simple & Lightweight Stack: Runs completely on Node.js, Express, and MongoDB without requiring external heavy third-party message brokers.

Keywords: Emergency Response, Web Application, Node.js, Express, MongoDB, 2dsphere Index, Geospatial Proximity, Leaflet.js.

Chapter 1: Introduction & Problem Statement

Emergency response systems play a vital role in public safety by coordinating help during accidents, medical emergencies, and natural disasters. Timely intervention can mean the difference between life and death.

1.1 Background & Motivation

Most conventional emergency helplines rely heavily on voice calls. During high-stress situations or severe disasters, this conventional approach faces several common challenges:

  • Location Ambiguity: Callers often cannot describe exact street addresses or landmarks, especially in unfamiliar or flooded areas.
  • Manual Dispatching: Dispatchers have to manually look up unit locations, which slows down the dispatch process.
  • Lack of Real-Time Overview: Coordinators do not have a single unified map showing where all open incidents and available units are located simultaneously.

1.2 Problem Statement

"To develop a simple, responsive, and real-time emergency dispatch web application that allows citizens to report incidents with precise GPS coordinates and enables emergency dispatchers to instantly identify and assign the closest available response team using geospatial indexing."

Chapter 3: System Architecture & Workflow

GeoPulse follows a standard 3-tier client-server architecture consisting of the presentation layer (frontend), application layer (Node.js backend), and database layer (MongoDB).

3.1 Three-Tier Architecture

  • Frontend Layer: Built using HTML5, CSS3, JavaScript, and Leaflet.js. It provides the citizen SOS reporting panel, incident list, and interactive map.
  • Backend Layer: An Express.js REST API server running on Node.js (port 5000). It receives requests from the frontend, validates parameters, and interacts with MongoDB.
  • Database Layer: MongoDB Community Server storing BSON documents with 2dsphere indexes for fast spatial queries.
Figure 3.1: GeoPulse System Architecture Diagram

3.2 Project Workflow

  1. Incident Submission: Citizen enters name, contact, incident category, victim count, and selects location on the map.
  2. Database Storage: Backend saves the report as a GeoJSON Point in the incidents collection.
  3. Proximity Search: Dispatcher clicks 'Match Unit'. The backend triggers a $geoNear query to find available squads within 15 km.
  4. Assignment & Routing: The best match is assigned, and a dashed route line connects the team to the victim on the map.
  5. Resolution: Once aid arrives, the dispatcher clicks 'Resolve', closing the incident.

Chapter 5: Proximity Search & Backend Implementation

Finding the closest rescue unit is the core feature of GeoPulse. Rather than writing slow distance calculations in JavaScript loops, the search is handled directly by MongoDB's $geoNear aggregation pipeline.

Figure 5.1: Proximity Search Pipeline and Fallback Matching Workflow

5.1 The $geoNear Aggregation Code (in server.js)

const pipeline = [
  {
    $geoNear: {
      near: { type: 'Point', coordinates: [parseFloat(incidentLng), parseFloat(incidentLat)] },
      distanceField: 'distanceMeters',
      spherical: true,       // Calculates accurate distance over spherical Earth surface
      maxDistance: 15000,    // Search within 15 km radius
      query: { status: 'Available' }
    }
  },
  { $limit: 3 } // Returns top 3 candidate units with distance
];
const nearest = await db.collection('responders').aggregate(pipeline).toArray();

5.2 Fallback Auto-Assignment

In rural or remote areas where no pre-registered unit is currently free within 15 km (nearest.length === 0), GeoPulse automatically generates and provisions a local emergency volunteer unit nearby so that every distress beacon receives an assigned responder.

Chapter 8: How to Run the Project & API Endpoints

GeoPulse is completely self-contained and easy to set up on any standard computer with Node.js and MongoDB installed.

8.1 Step-by-Step Execution Guide

Step 1: Start MongoDB Service
Ensure MongoDB is running locally on port 27017. In Windows command prompt, run: net start MongoDB.

Step 2: Start Node.js Backend Server
Open terminal in the geopulse-backend/ folder and run: node server.js. The server starts at http://localhost:5000.

Step 3: Open in Browser
Open your web browser and navigate to http://localhost:5000. You can also double-click start.bat in the project folder to launch everything automatically.

Chapter 9: Conclusion, Future Scope & References

9.1 Conclusion

The GeoPulse project successfully demonstrates a practical, working web application for real-time emergency dispatch coordination. By using Node.js, Express, and MongoDB geospatial features (2dsphere index and $geoNear pipeline), the application quickly matches citizens in distress with the nearest available emergency response team.

The system provides an intuitive map-based interface, automated distance calculation, route line rendering, and clean data management. It provides a simple, functional solution to the delays commonly encountered in traditional manual emergency dispatch systems.
