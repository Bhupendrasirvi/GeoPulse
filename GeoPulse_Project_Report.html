1. Introduction

During disasters like flash floods, structural fires, or building collapses, getting emergency squads to the scene quickly is critical. Traditional emergency helplines often waste precious minutes because operators have to manually write down landmarks and search through static lists to find who is available.

GeoPulse is a fast, web-based emergency dispatch platform that connects citizens in danger with the nearest available rescue teams and relief shelters. By taking advantage of MongoDB's built-in 2dsphere location search, GeoPulse calculates true spherical distances in less than 20 milliseconds without needing complicated external message brokers.

2. Project Objectives

  • Sub-20ms Location Matching: Use MongoDB's 2dsphere index to find the nearest rescue team within 15 km in less than 20 milliseconds.
  • Simple Citizen SOS Portal: Give citizens a 1-tap mobile form to drop their GPS pin, select their emergency category, and request help.
  • Autonomous 48-Hour Cleanup: Use MongoDB's Time-To-Live (TTL) feature to auto-delete resolved alerts after 48 hours without needing manual cleanup scripts.
  • Smart Report Stacking: Group duplicate calls from the same location into a single card with a counter (e.g. x3 reports) to prevent screen clutter.
  • Local Backup Team Creation: Automatically register a local community squad if no team exists within 15 km so no victim goes unattended.
  • Zero Broker Dependency: Keep the system simple with Node.js and MongoDB without needing Redis or Kafka.

4. How the System Works (Dual Workflows)

A. For Citizens in Need:

  1. Open the portal and click "Use My GPS" or click on the map to set a location pin.
  2. Select the emergency category (Medical, Flood, Fire, Supplies) and victim count.
  3. Click "Transmit Emergency SOS Beacon". The alert is saved immediately into MongoDB in <30ms.

B. For Dispatchers & Coordinators:

  1. The dispatcher sees a clean, color-coded feed of open emergencies (Red = Action Needed, Blue = En Route, Green = Resolved).
  2. Click "Match Unit" (or press M). The system queries MongoDB and draws a blue route line to the nearest squad.
  3. When rescue is complete, click "Resolve" (or press R). This activates the 48-hour auto-delete timer.

6. Key Features & Implementation

Feature 1: Finding Nearest Team using `$geoNear`

Instead of calculating distances manually in JavaScript, MongoDB computes spherical distance directly in C++: 

// Executed inside server.js on /api/match
const pipeline = [
  {
    $geoNear: {
      near: { type: "Point", coordinates: [lng, lat] },
      distanceField: "distanceMeters",
      spherical: true,       // Computes true distance over Earth's ellipsoid
      maxDistance: 15000,    // 15 km search radius
      query: { status: "Available" }
    }
  },
  { $limit: 3 } // Top 3 closest available squads with ETAs
];
const nearestTeam = await db.collection('responders').aggregate(pipeline).toArray();

Feature 2: 48-Hour Self-Cleaning (TTL Index)

// Created once in server.js on startup:
db.incidents.createIndex(
  { resolvedAt: 1 }, 
  { expireAfterSeconds: 172800 } // 172,800 seconds = exactly 48 Hours
);

Once marked resolved, MongoDB automatically removes the record after 48 hours without requiring background cron scripts.

Feature 3: Operational Keyboard Hotkeys

  • / — Jump to search box
  • J / K — Move up/down incident list
  • M — Match and dispatch nearest squad
  • R — Mark incident as resolved (starts 48h TTL)
  • N — Simulate incoming emergency call

7. REST API Endpoints

Method Endpoint Description & Database Action
GET /api/incidents Fetches all active and resolved emergency incidents.
POST /api/incidents Receives new citizen SOS beacon data and inserts document into MongoDB.
GET /api/responders Lists all emergency squads, coordinates, and availability status.
POST /api/match Executes $geoNear to calculate and assign the closest team in ~14ms.
POST /api/resolve Marks incident resolved and activates 48h TTL purge timer.

9. How to Run the Project Locally

  1. Start MongoDB: net start MongoDB (runs on port 27017).
  2. Start Backend: In geopulse-backend/ run node server.js (runs on port 5000).
  3. Open Frontend: Open http://localhost:5000 in any web browser, or double-click start.bat.

10. Conclusion

The GeoPulse project proves that an effective, mission-critical emergency dispatch system does not require over-complicated cloud infrastructure or expensive commercial software. By consolidating coordinate storage, spherical proximity matching ($geoNear), and autonomous lifecycle cleanup (TTL) directly inside MongoDB, GeoPulse connects victims with responders in sub-second time, helping save critical minutes during real-world crises.
